## 1. 요금 종류 선택 방식 변경 (RecordFormFields.tsx)

### 배경
기존에 "직접입력"이라는 별도 버튼이 있어, 이를 선택하면 `fee_type = "직접입력"`이 DB에 저장됨. 엑셀 출력 시 실제 요금 종류명(신경계 등) 대신 "직접입력"이 표시되는 문제 존재.

### 변경 내용
- "직접입력" 버튼 제거
- 요금 종류(신경계, 근골격계 등) 선택 후 금액을 직접 수정 가능하도록 변경
- 요금 종류 버튼 선택 시 기본 단가가 입력칸에 자동 채워지며, 사용자가 덮어쓸 수 있음
- DB 및 엑셀에 실제 요금 종류명이 기록됨

### 영향 파일
- `src/components/ui/RecordFormFields.tsx`

## 2. 건수 수정 시트 — 요금 종류 UI 복원 (RecordEditSheet.tsx)

### 배경
이전 세션에서 건수 기록 수정 시 요금 종류 선택이 불가했던 문제를 수정한 상태. 이번 세션에서 가격 표시 및 금액 직접입력 필드 포함 여부를 재논의 후 최종 확정.

### 최종 UI 결정
- 요금 종류 버튼: 요금명 + 금액(`/회`) 표시 유지
- 버튼 선택 후 금액 직접입력 필드 노출 (기본단가 자동입력, 수정 가능)

### 영향 파일
- `src/components/ui/RecordEditSheet.tsx`

## 3. 전액 바우처 결제 수정 시 미반영 버그 수정 (RecordEditSheet.tsx)

### 원인
`RecordFormFields` 컴포넌트에 `allowVoucherAsPrimary` prop이 전달되지 않아 수정 시트에서 "전액 바우처" 버튼이 표시되지 않음.

또한 저장 시 `payment_method === 'voucher_only'`인 경우 그대로 DB에 저장되는 버그 존재 (`voucher_only`는 프론트 전용 값).

### 변경 내용
- `RecordFormFields` 호출에 `allowVoucherAsPrimary` prop 추가
- 저장 payload에서 `payment_method === 'voucher_only'`이면 `secondary_methods[0]`으로 변환 후 저장

### 영향 파일
- `src/components/ui/RecordEditSheet.tsx`

## 4. 건수 탭 요금 종류 버튼 금액 표시 복원 (PaymentPage.tsx)

### 변경 내용
일시적으로 제거했던 건수 탭 요금 종류 버튼의 금액 표시(`/회`) 복원.

### 영향 파일

## 기술 메모

- `voucher_only`는 프론트엔드 전용 `PaymentMethod` 값으로, DB 저장 시 항상 실제 바우처 방식으로 변환 필요
- `RecordFormFields`의 `allowVoucherAsPrimary` prop은 신규 입력(DailyInputPage, PaymentPage)과 수정(RecordEditSheet) 모두에서 일관되게 전달되어야 함
