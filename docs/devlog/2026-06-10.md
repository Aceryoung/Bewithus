## 1. 개발자 계정 생성 (Supabase Admin API)

### 배경

원장(director) 비밀번호를 모르는 상황에서 새 개발자 계정이 필요했음. Supabase SQL Editor로 `auth.users` 직접 삽입을 시도했으나 GoTrue 내부 필드(`raw_user_meta_data.sub`, `auth.identities`, `raw_app_meta_data`) 누락으로 로그인 500 오류 반복.

### 근본 원인

- SQL로 `auth.users`를 직접 삽입하면 GoTrue가 요구하는 여러 내부 필드가 초기화되지 않아 `signInWithPassword` 시 500 반환
- 신뢰할 수 있는 유일한 계정 생성 방법: Supabase Admin API(`auth.admin.createUser()`)

### 해결 방법

1. `scripts/create-dev-account.mjs` 임시 스크립트 작성 — service role key로 `admin.auth.admin.createUser()` 호출
2. 기존 불완전 계정(`auth.users` + `public.users`) 삭제 후 새 계정 생성
3. 스크립트 실행 성공 즉시 파일 삭제

### 결과

| 항목 | 값 |
|------|----|
| 이름 | 개발자 |
| 역할 | director |
| 지점 | 1호점 |
| PIN | 9999 |
| 이메일(내부) | `{uuid}@bewithus.internal` |

### 보안 사항

- service role key는 스크립트 내에서만 사용, 실행 직후 파일 삭제
- 프로젝트 파일, `.claude/` 설정, git log, git stash 전 범위 검색으로 키 잔류 없음 확인

## 2. 횟수 입력 16회 리밋 제거

### 배경

결제 횟수 입력 필드에 `max={16}` 및 `Math.min(16, ...)` 하드캡이 존재해 16회 초과 입력 불가.

### 변경 내용

세 파일에서 상한 제약 제거, 하한(최소 1회, 0.5 단위 허용 시 최소 0.5) 유지.

**RecordFormFields.tsx**
- half-session onChange: `Math.min(16, ...)` 제거 → `Math.max(0.5, Math.round(num * 2) / 2)`
- half-session onBlur: 동일
- normal onChange: `max={16}` 제거 + `Math.min(16, ...)` 제거

**RecordEditSheet.tsx**
- 건수 수정 input에서 `max={16}` 제거

**PaymentPage.tsx**
- 위와 동일한 패턴 3곳 제거

### 영향 파일

- `src/components/ui/RecordFormFields.tsx`
- `src/components/ui/RecordEditSheet.tsx`
- `src/pages/teacher/PaymentPage.tsx`
